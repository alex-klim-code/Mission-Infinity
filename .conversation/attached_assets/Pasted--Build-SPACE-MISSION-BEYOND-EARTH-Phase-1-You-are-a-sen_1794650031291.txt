# Build SPACE MISSION: BEYOND EARTH — Phase 1

You are a senior full-stack game developer, software architect, multiplayer systems engineer, and UI/UX designer.

Build a complete, production-ready foundation for a browser-based, story-driven, cooperative space mission game called **SPACE MISSION: BEYOND EARTH**.

This project is being developed for the **2026 NASA Space Apps Challenge — Space Mission Design Game**.

The challenge focuses on helping players understand the real engineering decisions involved in planning and managing space missions, including spacecraft design, budgets, mass, power, communications, scientific instruments, launch vehicles, orbital constraints, and mission success.

The complete game will eventually include realistic spacecraft design and mission simulations.

**However, this development phase must stop immediately before the actual mission gameplay begins.**

Implement everything from authentication and character creation to the cinematic introduction, mission briefing, and final START MISSION screen.

Do not implement spacecraft engineering, mission simulation, rocket selection, orbital calculations, or the actual mission gameplay yet.

The result must be a fully working, visually polished, deployable web application with real multiplayer functionality.

# 11. STORY MULTIPLAYER SYNCHRONIZATION

The story introduction must be synchronized between players.

Requirements:

- All players see the same current scene.
- The server stores the current scene.
- The host controls progression to the next scene.
- Other players can indicate they are ready to continue.
- A player refreshing the browser returns to the current scene.
- Late joins are not allowed after the story begins.
- Disconnected players can reconnect to the same session.
- All players must accept the mission before the final transition.

Implement scene state on the backend.

Suggested states:

```typescript
type SessionStatus =
  | "LOBBY"
  | "STORY"
  | "MISSION_BRIEFING"
  | "MISSION_ACCEPTANCE"
  | "READY_TO_START"
  | "MISSION_STARTED";
```

Only allow valid state transitions.

Prevent clients from skipping directly to later scenes by manipulating API requests.
